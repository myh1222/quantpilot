# QuantPilot 当前代码审查（2026-09-15）

## 结论

当前代码可以继续作为单机 MVP 开发。账户域、AI 结构化输出和追问上下文此前各有一个会造成错误或语义混乱的问题，本轮已修正。尚未发现阻止本地技术分析、自选股或账户持仓功能运行的 P0 问题。

## 本轮已修正

### 1. 账户不是持仓文本字段

旧实现把 `account_name/equity/cash` 混在每条持仓保存，无法表达空账户、多账户和多币种现金。现改为独立 `accounts`、`cash_balances`、`positions.account_id`，并提供旧数据事务迁移。

### 2. AI 返回结构不兼容

兼容 Chat Completions 的模型可能忽略 Schema，只返回 `{stance, reason}`。现首次校验失败后自动发起一次结构修复；再次失败只返回稳定的协议错误，不再把 Zod issue 列表直接显示在页面。

### 3. AI 追问信任了浏览器回传结果

旧追问接口接收整份 `result`，浏览器可篡改技术数据，而且页面临时 Key 场景可能触发空服务端 Key。现改为服务端内存会话：成功分析返回随机 `analysisSessionId`，追问只提交 ID 和消息；仅存在服务端管理 Key 时启用。

### 4. TradingView 启动说明与实现不一致

Provider 已改成连接系统 Chrome 的本机 CDP，但文档仍要求 `tradingview:login`。现统一为 `npm run tradingview:open`，并明确调试端口只能绑定 `127.0.0.1`。

## 保留风险

### P1 — 账户级实时估值尚未实现

当前只有正在分析的股票获得最新价格；同账户其他持仓只保留成本和风险位。因此不能把其他持仓成本误称为实时市值，也不能在没有 FX Provider 时计算跨币种净值、现金占比和集中度。设计已将这项能力留到 Quote/FX 快照接入后。

### P1 — TradingView Data Window 仍依赖现场验证

DOM 选择器、Pine `QP_*` 字段和脚本版本检查都已 fail closed，但真实账户下的当前 TradingView UI 仍需完成一次端到端验收。失败时只降级本地行情，不影响基础分析。

### P1 — 行情 Provider 仍是可替换 MVP 实现

Yahoo/Tencent 当前承担行情和搜索兜底，延迟、频率和数据许可仍需在正式分发前确认。账户级估值不能建立在未定义的数据新鲜度上。

### P2 — 账户仓位读取存在 N+1 查询

`listPositions()` 会为每条持仓读取同账户现金和仓位摘要。自选规模较小时可接受；当持仓超过约 100 条时，应改成批量加载后在内存分组。

### P2 — 迁移按文件名记录

`schema_migrations` 只记录文件名、不记录 checksum。已应用迁移必须保持不可变，后续结构变化只能新增迁移文件；否则现有数据库不会重新执行被修改的旧文件。

### P2 — 追问会话是进程内状态

会话最长 1 小时、最多 100 个，进程重启后失效。这符合单机 MVP；若以后多实例部署，需要迁移到持久化 session store，并继续只通过不透明 ID 引用上下文。

## 验证重点

1. 旧 `account_profiles + positions.account_name` 数据升级后账户、现金和持仓数量不变；
2. 一个账户可有 0..N 持仓及 0..N 个不同币种现金余额；
3. 有持仓的账户和自选股不能删除；
4. AI 首次返回错误字段时只重试一次，错误信息不泄露校验详情；
5. 未勾选共享仓位时，账户、现金和持仓均不发送给 AI；
6. 勾选后仍不发送账户名称、本地 ID 和现金备注；
7. 追问只能引用服务端生成且未过期的分析会话。
